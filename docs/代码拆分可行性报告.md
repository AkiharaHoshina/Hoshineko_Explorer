# App / ExplorerTab / FilePicker 代码拆分可行性报告

> 状态：第一批已实施（2026-10-21，v3.0.1001）；后续阶段待排期。
> 目标：降低单文件体量、减少改动回归面，同时保持 110 套 e2e 全绿。

## 一、现状

| 文件 | 行数 | 职责 |
| --- | ---: | --- |
| `src/App.tsx` | 3324 | 全部应用状态（标签页/固定项/仪表盘/设置/对话框/全局快捷键/菜单构建）+ 主布局 |
| `src/components/ExplorerTab.tsx` | 3412 | 单标签页：导航/搜索/选择/键盘/拖放/预览/顶栏/内容分派 |

| `src/components/FilePicker.tsx` | 1687 | 选择器 + 保存器共用一个组件（模式分支遍布） |

具体问题：

1. **状态与视图耦合**：AppContent 约 3185 行，任何状态改动都在同一个渲染函数内，
   React Compiler 对 App.tsx 已 bail out（文件级 eslint-disable），依赖数组靠人工维护。
2. **选择器/保存器模式分支分散**：`isSave` 在渲染、事件、搜索门控、冲突处理中反复出现，
   阅读时需要来回跳转。
3. **81 个 props 的 ExplorerTab**：新增功能倾向于继续加 prop，回调内联导致无法 memo。
4. **回归面大**：改一个菜单动作可能触及整个 App.tsx，e2e 只能整套跑才能放心。

## 二、不可破坏的约束

- **无路由**：标签页状态在 App.tsx，虚拟路径即 tab 身份；不能引入 React Router 改变模型。
- **隐藏标签页常驻 DOM**（`display:none`）：e2e 依赖该行为；拆分时不得改为条件卸载。
- **CSS 同目录平铺**、类名被 e2e 大量断言：拆组件时保留原类名与 DOM 结构。
- **SettingsContext 单一数据源**：页面不自建 `useLocalStorage`；拆 hook 时保持 App 持有。
- **harness 手工副本**：本报告只动渲染层，不改 `main.ts` 顶层注册，无需同步 harness。
- **React Compiler 阈值**：拆出的单文件不要再次逼近阈值；AppContent 目标 < 1200 行。

## 五、风险与对策

1. **回调身份变化引发额外渲染**：抽 hook 时所有返回函数用 `useCallback`，依赖数组完整；
   拆分不做「顺手优化」，行为变更单独提交。
2. **e2e 选择器耦合 DOM/类名**：拆组件时复制原 JSX 结构，不改类名；新增 wrapper 需确认
   `elementFromPoint`/`querySelector` 断言不受影响（软件渲染下坐标点击敏感）。
3. **隐藏标签页渲染**：拆 `ExplorerContent` 时保持每标签一个常驻 wrapper，仅切 `display`。
4. **懒加载边界**：从懒加载组件导入的非组件常量会重新拉回主 chunk（本轮 `DEFAULT_TERMINAL_HEIGHT`
   的教训）——常量/类型放独立小模块。
5. **React Compiler**：新文件保持函数组件 + hook 规则；若再次越过阈值，按模块继续拆，不关闭规则。
